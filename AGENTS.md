- always run `make build` after every code change that would result in a new binary output. Do not worry about `make build` for documentation-only changes, github workflow updates, etc. You must ensure that the `make build` exit code is 0 before considering the work to be completed. The `build` target runs the linter (with `check-no-team`, `check-private-names` and the SwiftLint self-test), the package and app unit tests, and the macOS, iOS simulator and tvOS simulator builds, so you don't need to run any other make commands to ensure the changes are not breaking.

- here are the general linter rules to know before you write/change code. try to adhere to these when making changes, and especially before running `make build` so you don't have to do rework because the linter reported violations that could have been avoided by following the basic rules from the start.
  - max 400 lines per file. check file line lengths and use multiple files to avoid linter violations.
  - max 120 characters per line. break up long lines
  - var/let names and struct field members should be at least 3 characters long (`id` and `url` are allowed)
  - function bodies should be < 150 lines, not counting comment lines
  - type bodies should be < 400 lines
  - cyclomatic complexity of 15 or less per function (`make lint` uses `--strict`, so the warning level fails)

- do not use the plus (+) character in filenames.

- Consolation is a free live TV and video player for legal sources (HDHomeRun tuners, stream URLs), with the original capture card viewer as its Capture Card pane. The roadmap isn't kept in this repository; when a local `TODO.md` (gitignored) is in the repository root, it is the plan to follow.

- never name a private project or internal host in this public repository. `make lint` fails when a tracked or new file contains a name listed in the untracked `Local.private-names` (one per line, case-insensitive).

- substance goes in local Swift packages under `Packages/` (HTTPMPEG2Kit, PlaybackKit, MediaSourceKit, PlayerKit). EtagereKit is its own public repository (https://github.com/centennial-oss/EtagereKit, Apache-2.0) that the project adds by URL and version. Packages are app-agnostic: no Consolation branding, no `AppIdentifier`, `UserDefaults.standard`, environment variables or notification names inside; identifiers, storage and switches are injected (for example `PlaybackHealthTrace.isEnabled`, which the app sets at launch). When a package is created, add it to the project, `.swiftlint.yml`, `PACKAGES` in the Makefile and CI in the same change. Packages use Swift 6 language mode and the app's upcoming features (including `MemberImportVisibility`); those with views or main-actor-facing models (PlaybackKit, PlayerKit) set `defaultIsolation(MainActor.self)`, the others mark their value types `nonisolated`.

- Consolation is multiplatform: macOS 26.0, iOS/iPadOS 26.0 and tvOS 27.0, from one `Consolation` target. Every change must compile for all of them (`make build` builds all three SDKs). Prefer APIs that exist everywhere and use `#if os(...)` sparingly, keeping platform-specific code small and isolated (e.g. a per-platform file or view modifier) rather than scattered through shared code. The capture card code is Mac and iPad only: it is compiled out of tvOS (`#if !os(tvOS)`), and `CaptureCardSupport.isAvailable` hides the pane on iPhone. Layout comes from the window's width (`ShellLayout`), never from the device type or orientation.

- the target uses Swift 6 with `MainActor` default isolation (`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, approachable concurrency). Keep views and UI state on the main actor, in `@Observable` models (no `ObservableObject` or Combine). Networking, stream parsing, decoding, file scanning and other heavy work must be `nonisolated` and run in `@concurrent` functions (or their own actors) so the UI never blocks; several live streams can play at once, so keep per-stream work lean and off the main actor. `AVCaptureSession` configuration, `startRunning()` and `stopRunning()` happen only on the `CaptureSessionBackend` actor, and capture sample buffers are handled on their delegate queues.

- the capture card viewer (Capture Card pane) has load-bearing ordering:
  - Keep `CaptureVideoPreview` mounted even while idle. The preview layer must hold the session before `startRunning()`, or UVC devices fall back to about 25 fps.
  - Mute is enforced by not scheduling audio buffers, not by mixer volume, and persisted mute is applied before capture starts so the first samples stay silent.
  - On iPadOS, `AVAudioEngine` start, stop and attach run on the main thread, and the audio session is `.playAndRecord` only while capture runs (`PlaybackAudioSession.captureEnded()` restores `.playback`).
  - Capture and the player never play at once, and capture stops once no window shows the pane.
  - Before a release, and after any change to capture, audio or the viewer, run the capture regression checklist on a Mac and an iPad: the capture cards listed as tested in `README.md`, the delivered frame rate (Video Stats overlay), audio latency and mute, hot-plugging the card, and rotate/mirror.

- never set a development team in `Consolation.xcodeproj/project.pbxproj` or a checked-in `.xcconfig`. Local builds use "Sign to Run Locally" and maintainers put their team in the untracked root `Local.xcconfig` (included by `Consolation/Version.xcconfig`). `make lint` (and so `make build` and every CI workflow) fails if a team is set. The release workflows (`.github/workflows/release-build.yml`) pass the team from the `APPLE_TEAM_ID` secret. Don't set MARKETING_VERSION or CURRENT_PROJECT_VERSION in the project file either; they live in `Consolation/Version.xcconfig`, which the release workflow rewrites.

- the macOS app is sandboxed. Its entitlements come from the target's `ENABLE_APP_SANDBOX`, `ENABLE_RESOURCE_ACCESS_CAMERA`, `ENABLE_RESOURCE_ACCESS_AUDIO_INPUT`, `ENABLE_USER_SELECTED_FILES`, `ENABLE_OUTGOING_NETWORK_CONNECTIONS` and `ENABLE_INCOMING_NETWORK_CONNECTIONS` build settings (incoming only to receive UDP tuner discovery replies); there is no entitlements file. Add a capability only when a feature truly needs it.

- `Consolation/Info.plist` is merged with Xcode's generated Info.plist. Prefer `INFOPLIST_KEY_*` build settings for simple string keys (`NSLocalNetworkUsageDescription`, the camera and microphone usage text) and use the file only for dictionaries such as `NSAppTransportSecurity`. Keep `Info.plist` and `Version.xcconfig` in the synchronized group's membership exceptions so they're never copied into the app bundle.

- privacy is a feature. Never add analytics, tracking, advertising, crash reporting or telemetry SDKs. Consolation makes no network connections until the user adds a source or plays a Quick Play URL, and then only to the sources the user configures (HDHomeRun tuners, stream URLs); with only a capture card it makes none at all. Local-network discovery runs only when the user asks for it, and `LocalNetworkGate` explains Local Network access before the first action that reaches the local network. Any cloud service must be opt-in, off by default, explained in the UI and itemized in `PRIVACY.md` in the same change. Any hard-coded `https://` host in `Packages/MediaSourceKit` or `Packages/HTTPMPEG2Kit` must also be listed in the repo-root `PRIVACY-HOSTS.txt`; a unit test fails otherwise.

- UI tests live in `ConsolationUITests/` and use XCTest (Swift Testing can't drive `XCUIApplication`); `make test-ui-tvos` runs them in the tvOS simulator. They are not part of `make build`; run them after any change to the shell, sidebar, panes or focus, and add a test for every focus or navigation bug you fix. Don't assume a UI was seen working unless it was driven, on a simulator or a device.

- running on simulators and real devices: `make run-macos`, `make run-sim-iphone`, `make run-sim-ipad`, `make run-sim-tv`, and `make run-device DEVICE="<name>"` for a paired iPhone, iPad or Apple TV (it builds, installs and launches with the device console attached; `xcrun devicectl list devices` lists names; it needs your team in `Local.xcconfig`). `make run-release DEVICE="<name>"` does the same with a Release build. All take `CHANNEL=`, `PANE=`, `TRACE=health|focus|all` and `ARGS=`, except that Release builds ignore `CHANNEL=`, `PANE=` and `ARGS=` (debug launch actions). `TRACE=health` prints a per-second playback health line and `TRACE=focus` prints every Apple TV focus move. Simulators have no capture devices, so the Capture Card pane needs a Mac or a real iPad with a card. Read the console to diagnose; don't guess.

- unit tests use Swift Testing (`import Testing`) in `ConsolationTests/` and in each package's `Tests/`. They run on macOS (`make test`) and must not need the network, real devices or the user's media; use fixtures (e.g. sample `discover.json` / `lineup.json` payloads) instead, and keep testable capture logic in pure helpers rather than behind `AVCaptureDevice`.

- fixtures and docs never contain `DeviceAuth`, tokens, LAN IP addresses, real HDHomeRun DeviceIDs or server names. Rewrite captured payloads before committing (for example `TargetIP` to 192.0.2.x and a synthetic DeviceID).

- manual tests against a real HDHomeRun: tuners are a shared household resource. Check `status.json` first, use `?duration=`, hold at most one tuner, and run one test at a time. Never call `/lineup.post` or start a channel scan.

- licensing: no GPL code. LGPL only as dynamically linked frameworks with full compliance: FFmpeg's `libavcodec` and `libavutil`, built unmodified by `make ffmpeg` (`scripts/build-ffmpeg.sh`), credited in `NOTICE` and Settings › About, with `LICENSES/LGPL-2.1.txt` bundled (`make lint` checks PlaybackKit's copy matches). Clean-room only where GPL or LGPL code shows the way; copy nothing.

- naming: never name packages, modules or general code after a third-party product or brand (for example, no "HDHomeRunKit"), so nothing can be mistaken for the vendor's own software. The tuner package is `HTTPMPEG2Kit`. A vendor name may appear only on the client types that speak its protocol, named `…Client` (`HDHomeRunClient`, `HDHomeRunStreamClient`, `HDHomeRunClientError`), on their direct callers and adapters, and in user-facing text. Models and helpers use generic names (`TunerDiscovery`, `TunerDeviceID`, `LineupChannel`, `ChannelKey`).
